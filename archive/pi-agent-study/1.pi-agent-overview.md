## 项目整体结构

这是一个 TypeScript / Node.js monorepo，主要由四个 package 组成：

| 路径 | 作用 |
| --- | --- |
| `packages/ai` | 多模型 provider 抽象层，封装 OpenAI、Anthropic、Gemini、DeepSeek 等模型接口。 |
| `packages/agent` | Agent runtime 核心，负责 agent loop、消息状态、工具调用、turn 循环。 |
| `packages/coding-agent` | `pi` CLI/TUI 主应用，包含命令行入口、交互模式、session、skills、extensions、本地工具等。 |
| `packages/tui` | 终端 UI 渲染层，支撑 interactive mode 的 TUI。 |

可以把它理解为：

```text
CLI/TUI -> AgentSession -> Agent Loop -> LLM Provider -> Tool Calls
```

其中最值得先读的文件：

```text
packages/coding-agent/src/cli.ts
packages/coding-agent/src/main.ts
packages/coding-agent/src/core/agent-session.ts
packages/coding-agent/src/core/agent-session-runtime.ts
packages/agent/src/agent-loop.ts
packages/ai/src
```

## 是否可以增加日志

可以增加日志，但建议写文件日志，不建议直接 `console.log`。

原因是 interactive mode 使用 TUI 渲染，直接向 stdout 打日志容易破坏终端界面。

项目中已经有一个 `/debug` 命令，会把当前 TUI 渲染状态和 agent messages 写入：

```text
~/.pi/agent/pi-debug.log
```

相关代码位置：

```text
packages/coding-agent/src/modes/interactive/interactive-mode.ts
```

对应方法：

```text
handleDebugCommand()
```

如果想研究实现原理，建议新增结构化文件日志，优先加在这些层：

| 位置 | 建议记录 |
| --- | --- |
| `packages/agent/src/agent-loop.ts` | `turn_start`、LLM response start/end、tool call、tool result、stop reason。 |
| `packages/coding-agent/src/core/agent-session.ts` | session 事件、消息持久化、retry、compaction、agent run 生命周期。 |
| `packages/ai/src` | provider 请求边界、模型名称、stream 事件、错误信息。 |

日志内容建议避免写入完整 API key、OAuth token、隐私文件内容。比较安全的日志字段包括：

```text
timestamp
event type
provider
model
message count
tool name
tool call id
stop reason
duration ms
error name/message
```

## 注意事项

`npm install --ignore-scripts` 已成功执行，但 npm audit 报告了 2 个 critical severity vulnerabilities。

学习源码时暂时不建议执行：

```bash
npm audit fix --force
```

因为它可能改动依赖树，给源码阅读和调试引入额外变量。
